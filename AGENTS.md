# Project delivery

- Work on a dedicated branch and publish a pull request instead of pushing changes directly to `main`.
- Read the existing implementation before changing behavior. Preserve existing user data and server configuration.
- Run backend tests with `cd backend && APP_REPORTS_ENABLED=true python -m pytest tests -q`.
- Verify MySQL behavior on an isolated `test_` database using `TEST_DB_ENGINE=mysql` and `TEST_MYSQL_DATABASE`; never point tests at the application database.
- Run frontend checks with `cd frontend && npm ci && npm run build`.
- Run release/rollback checks with `python -m unittest discover -s deploy/tests -v` from the repository root.
- Describe the concrete change, validation results and remaining limitations in the pull request.
- Runtime secrets stay in the server `.env`; user images, database files and generated food-catalog audit data must not be committed.
- Food values generated by a model must retain `source_type=ai_estimate`, `verified=0`, per-100g units, preparation state and generation provenance.
- Merged `main` commits are eligible for deployment only after the named `ci.yml` workflow passes. Deployment acceptance must pass before activating a release; failures restore the previous application images.
