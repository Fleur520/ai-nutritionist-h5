# AI 咨询逐步显示

默认仍使用 `/api/chat/stream` SSE。后端直接读取模型增量，前端收到片段立即追加；
支持停止回答、错误重试与完整回答入库。服务密钥仅配置在后端。

## 缓冲隧道的兼容配置

部分临时 HTTP 隧道会等待响应结束再转发 SSE，单纯修改前端渲染不能解决。
在这类预览环境的 `frontend/.env.local` 配置：

```dotenv
VITE_CHAT_TRANSPORT=poll
```

重启 Vite 或重新构建前端。后端必须运行本分支且使用**单个 API worker**。
多 worker/多副本部署需先提供会话粘性路由或共享任务存储，否则使用默认 SSE。
没有改动现有生产部署脚本或数据库结构。

兼容方式只创建一次生成任务，服务端持续读取真实模型流，浏览器约每250ms加上请求耗时
取回新增 SSE 片段，立即显示。不是整段生成完后模拟打字，也不会为每次读取重新调用模型。
网络每次往返会影响更新频率。

- `POST /api/chat/jobs`：创建任务，返回任务 ID；同用户同对话只允许一个在途任务。
- `GET /api/chat/jobs/{id}?after=N`：读取 N 之后的片段及下一位置，不重复取整段。
- `DELETE /api/chat/jobs/{id}`：取消生成，释放模型并发名额。
- 所有接口沿用登录与来源检查，读取/取消必须属于当前用户，响应 `private, no-store`。
- 任务在 API 内存中有界保留；完成结果保留120秒，最多约128条。
  无读取20秒自动取消，生成最长180秒，输出总长度/事件数均有上限。
- API 重启会使在途任务失效；仅完整回复按现有流程存入聊天记录。
  停止或失败保留页面已有文字，不将它标为完整回答。

验收时记录至少两个生成未结束时的正文长度、最终长度和首段耗时；
验证停止、无权限访问、错误与正常历史回读，不能仅凭最终出现文字判定逐步显示成功。
