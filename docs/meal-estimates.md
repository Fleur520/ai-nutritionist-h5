# 照片模型营养估算与食品库关联

照片识别默认采用视觉模型返回的重量及每100克可食部热量、蛋白质、脂肪、碳水。食品库匹配仅用于关联参考，未匹配项可以保存，关联或更换食品编码不覆盖照片估算。用户显式切换“食品库参考”后，才采用所选食品库数据。修改重量时按相同每100克基准重新计算整份营养。

工作流生成时在已有优化选项之外启用 `--model-nutrition`。紧凑输出增加四项营养数值，仍只有一次视觉模型调用；范围、单位、非有限数及营养素总量均校验，缺失值不能作为零热量保存。旧工作流仍可返回不含营养的结果，此时需选择食品库参考。

识别接口签发保存在服务端的私有识别记录。保存餐食只提交该记录ID、项目索引、确认重量、可选食品编码及计算来源，服务端读取原模型估算计算总量。客户端提交的热量和“已核验”声明不作为模型结果使用，记录须属于当前用户及同一照片。

数据库仅新增 `meal_recognitions` 与 `meal_item_estimates` 两张表，启动时幂等创建，不修改旧表和已有数据。未匹配项在旧 `meal_items.food_code` 列使用空串，API返回null；名称、制作状态、每100克基准、`source_type=ai_estimate`、`verified=0`、平台模型ID及生成时间/工作流/应用版本保存在私有快照中。公共食品库和文档库不会因单次拍照自动扩充。历史记录和营养汇总读取保存时的总量。

旧版本可以继续读取已有总量；但旧版本使用食品库内连接的历史列表不能显示未匹配项目，回退会保留这些记录，重新部署本功能后恢复显示。发布必须协调应用与工作流版本，并在独立 `test_` 数据库完成照片识别、保存、回读和并发验收后再上线。照片估算始终未核验，测试响应速度不能证明营养准确率。
